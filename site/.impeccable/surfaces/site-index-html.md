## Scope and mode

- **Primary target:** `site/index.html`
- **Related targets:** `site/src/styles.css`, `site/src/main.js`
- **Visitor mode:** Persuade

## Visitor and job

Developers already using coding agents need to recognize the cost of approving
long plans without real review. The page should make Frank's narrow role obvious
in one viewport: isolate consequential calls, check them against the repository,
and talk them through locally.

## Action and proof

The primary action is to try the current unsigned macOS CI build; the secondary
action is to inspect the source. Proof comes from one clearly illustrative
47-step rate-limiting plan, three concrete decisions, a short spoken exchange,
and an exact note handed back to the agent.

## Direction

Treat plan review as an off-register print-proof studio. The memorable moment is
the interactive Frank pass: a squeegee crosses the synthetic plan and leaves the
three consequential lines pulled forward. The rest of the page alternates
between proof stock, dense ink fields, printed transcripts, duck editions, and a
local-pond stamp.

## Constraints

The page stays static, truthful, keyboard accessible, responsive, and deployable
at the `/frank/` GitHub Pages base path. It must not invent stable releases,
testimonials, usage metrics, or customer claims. Audio is never required to
understand the page.

## Unresolved decisions

Replace the CI artifact call to action with a signed release only when one
actually exists.
